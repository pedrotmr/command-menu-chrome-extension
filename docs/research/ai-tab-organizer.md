# AI tab organizer: research and prototype notes

**Updated:** 2026-11-05

**Scope:** personal, local prototype only. This does not select a production provider or authorize a Keybar rollout.

## Recommendation

Evaluate OpenAI's **Sign in with ChatGPT** open-source-app route first. It has a current, provider-authored local Node SDK that performs browser sign-in, encrypted credential storage, model discovery, and streaming Responses API calls. The official flow gives eligible users an explicit permission screen for plan usage; OAuth credentials stay in the local companion. Keybar's Chrome extension cannot run that Node SDK or safely manage its credentials itself, so the prototype uses Chrome Native Messaging to call a local Node host.

This is a research choice, not a production approval. The official DevKit is explicitly noncommercial; the open-source plan-usage route is intended for open-source/local apps and selected private apps. Do not ship this implementation in a commercial Keybar product without written rights and policy confirmation. The prototype pins the DevKit Git submodule commit and applies an idempotent local patch at setup to pass the reasoning-effort option; it remains out of the production extension build.

## Subscription, billing, and policy distinctions

- A local open-source app uses the account's eligible subscription allowance after the user signs in and grants plan-usage permission. It does not gain access to the user's ChatGPT conversations.
- OpenAI Platform API keys use API billing and are different from ChatGPT plan usage. Anthropic Console API use and any Console credits are distinct from Claude subscription usage; Cursor API-key cost rules need further verification. The current prototype no longer uses an Anthropic Console key.
- A remotely hosted service cannot silently reuse a user's local CLI or subscription credentials. OpenAI's app-server documentation says app-server authentication has not been permitted for commercial or hosted services and points commercial routes to Sign in with ChatGPT; the current OSS DevKit license also restricts its code to noncommercial use.
- Anthropic's legal guidance says developers building products that interact with Claude should use Console API-key authentication and may not intermediate Claude subscription credentials. The same page says an end user may sign in to the unmodified Claude Code binary with their own subscription. This prototype opens the installed CLI and leaves sign-in and credentials with Claude Code; review the terms before broader distribution.
- Cursor's supported CLI login and headless command mode are documented. That alone does not answer whether another product can redistribute or automate the CLI as a subscription feature.

## Extension and companion boundary

An extension can request tabs, groups, and native messaging, but it cannot run Node.js or provide a trustworthy OAuth token vault. The Codex route keeps OAuth and inference in the native host. For Claude, the host launches the unmodified Claude Code CLI; Claude Code itself owns sign-in, credentials, and inference. The app never extracts, copies, or stores Claude credentials. Both routes return only a validated proposal. The extension receives tab IDs/names/URLs to display and uses current Chrome APIs only after the user chooses changes.

Chrome Native Messaging uses a length-prefixed JSON stdio protocol. The host's manifest must list the exact extension origin; wildcards are not allowed. Chrome locates host registrations by operating system. Chrome Web Store delivery covers the extension but does not install a general native helper for every user, so a production release would need separately maintained, signed installers and update/uninstall paths for macOS, Windows, and Linux, along with disclosure and support. This prototype only implements macOS registration and Keychain-backed Codex credential encryption.

## Data, safety, and recovery

- Default analysis sends each tab's title, up to 2,048 URL characters, pinned state, existing group name, and a temporary request-local numeric handle to the selected provider. The handle is not the Chrome tab ID and is discarded after the response. For Claude, the local CLI receives this metadata on stdin and sends it to Anthropic. Full URLs remain in the extension for stale-tab checks. The browser password store, page contents, cookies, and browsing history are not read. URL query strings can themselves contain sensitive data such as access tokens, and that text may be sent.
- The Codex SDK sets `store: false` in its Responses API request. Claude Code runs in safe mode, with built-in and MCP tools disabled and session persistence off. In both routes, model output is parsed and checked against the current snapshot. A title or URL is treated as untrusted text.
- The review screen selects groups by default, but close candidates remain unchecked. Pinned tabs are skipped during grouping and excluded from closure. Application rechecks that Chrome tab IDs and URLs still match. A changed or closed tab is skipped, and partial failures are reported.
- The extension stores the title, URL, and window ID for recently closed tabs in session storage, allowing tabs to be reopened. Each closing batch replaces the saved list, so earlier batches cannot be reopened. Chrome clears `storage.session` when the browser restarts or the extension is disabled, reloaded, or updated. The extension cannot recover unsaved form state or other page memory.
- A cancelled, failed, or malformed response makes no browser changes. Missing sign-in and missing plan-use consent are separate states; network and plan-limit errors allow retry after recovery.

## Prototype and observed evaluation

The implementation is in [`prototypes/tab-organizer`](../../prototypes/tab-organizer/README.md). It creates seven local synthetic tabs across product docs, research notes, and trip planning, including an exact duplicate. The popup offers Codex models through ChatGPT plan sign-in and Claude Code through the user's local CLI sign-in, then exposes model and effort settings before requesting an AI proposal. Claude credentials remain in Claude Code's own configuration. The Codex app-server is used only for model catalog discovery; analysis uses the local SIWC SDK's direct no-tools Responses request. Claude analysis uses `claude -p` with stdin input and no enabled tools.

The native host prefers GPT-6 Luna when available in the signed-in account's model list and Claude Haiku for its default. The popup reads Codex effort support from the model catalog. Claude Code does not expose a subscription-specific model catalog, so the prototype offers documented aliases (`haiku`, `sonnet`, `opus`, and `fable`) and effort flags (`low` through `max`); the CLI checks account access and model compatibility on each request. The CLI has no non-reasoning effort option, so the Claude default is low effort. Setup applies a local patch to the pinned DevKit working tree to pass the selected effort and expose an access token only to the trusted native host for Codex catalog discovery; the pinned submodule commit remains unchanged. Provider model selection and reasoning requests have not yet been measured with live accounts.

Installing the full DevKit workspace reported 7 advisories (3 moderate, 4 high). The targeted `@siwc/local` runtime audit reported a high-severity advisory in its optional `undici` peer dependency. The SDK request path uses Node 22's built-in `fetch`, but the optional package is installed by the workspace and the advisory remains in the pinned upstream dependency tree. Review and resolve the dependency finding before any broader distribution.

### Setup and follow-up decisions

Run instructions and the noncommercial restriction are in the prototype README. Production work is not recommended until Pedro decides whether Keybar is strictly a personal/noncommercial tool or needs commercial distribution, whether a separately installed companion is acceptable, and whether extension metadata may leave the device for inference. If those conditions are acceptable, the candidate first-release issue is: **Add reviewed AI tab grouping through a separately installed macOS companion**. Keep page content out, require confirmation for closures, and limit the first release to Chrome on macOS. Before creating it, run a live synthetic-fixture session and record group precision, duplicate false positives, latency at 7/25/50 tabs, and rate-limit behavior; then compare OpenAI plan use with the Claude Code CLI route and a Console API-key route.
